# Navigating the code with ripwire

**ripwire** is a deterministic call-graph map of this repository. You point it at
a directory and it parses the code, ranks every symbol by importance, and streams
a compact map — so a human or an AI agent can locate the right code **before**
opening files. No LLM, no embeddings, no network: the same input always produces
the same bytes.

This repository uses ripwire as its architecture-mapping tool; the artifacts
under [`ripwire-out/`](../ripwire-out/) are its output.

## Install

ripwire is a standalone CLI, **not** a project dependency — like the previous
tool, it lives on your `PATH` rather than in `package.json`, so cloning this repo
does not pull it in. Once it is on `PATH`:

```bash
ripwire --version        # confirm the binary
ripwire . --doctor       # health: grammar, cache, index identity, git reachability
```

`--doctor` is the first thing to run if a symbol you expect is missing from the
map.

## What ripwire sees here

| Parsed | Notes |
|---|---|
| TypeScript / JavaScript (`src/`, `e2e/`, `demo/`) | call edges, symbols, metrics |
| Rust (`programs/healthaccess_audit/`) | the Anchor program |
| Python (`project_management/`) | the planning tooling |
| Markdown (`docs/`) | headings become section symbols |

**Not parsed:** `prisma/schema.prisma`. Prisma is not a ripwire language, so the
data model does not appear in the graph — read [`docs/diagrams/data-model.md`](diagrams/data-model.md)
(generated by `prisma generate`) for that instead.

## Common commands

```bash
# The ranked map of the whole repo (start here)
ripwire .

# Orient on a task: ranked, quality-annotated signatures for a task in words
ripwire . --for="how does the outbox flusher retry a failed anchor"
ripwire . --pack-task="add a new access-log action"     # signatures + callers + tests

# One symbol's body plus its callees' signatures — no whole-file read
ripwire . --expand=flushEntry

# Who reads/writes/calls a symbol
ripwire . --callers=flushEntry
ripwire . --uses=canonical_bytes

# Before writing new code: the repo's best in-class instance to imitate
ripwire . --exemplar="retry with exponential backoff"

# Before calling work done: only what your change made worse, then the test gate
ripwire . --quality-delta
ripwire . --test-gate
```

`ripwire . --help-task="<what you are doing>"` recommends the single best command
for the task and never executes it.

## Generated artifacts

Two artifacts are committed, mirroring the previous tool's outputs:

| File | Command |
|---|---|
| [`ripwire-out/graph.html`](../ripwire-out/graph.html) | self-contained interactive call graph (no CDN) |
| [`ripwire-out/GRAPH_REPORT.md`](../ripwire-out/GRAPH_REPORT.md) | architecture summary: modules, god files, cycles |

Regenerate both:

```bash
npm run ripwire          # graph + report
npm run ripwire:graph
npm run ripwire:report
```

The scripts pass `--exclude=ripwire-out` so the generated report does not list
itself. ripwire's warm parse cache lives in `TMPDIR`, not the repo, so nothing
else needs a `.gitignore` entry.

Extra views on demand (not committed):

```bash
ripwire . --mermaid      # module dependency graph as Mermaid
ripwire . --seams        # cross-module seams no test reaches
ripwire . --owners       # recency-weighted ownership / bus factor
```

## Wiring it into an AI agent

A binary on `PATH` is invisible to an agent until its rules file says when to
reach for it. `ripwire wrap` prints the exact recipe for the agent you use:

```bash
ripwire wrap claude      # or cursor | codex | aider | ...
```

This repo ships an [`AGENTS.md`](../AGENTS.md) with the quick-start so agents
that read it (Claude Code, opencode, Codex, Cursor, …) reach for ripwire instead
of blind `grep` + whole-file reads.

## Determinism

Output is byte-identical run to run (`ripwire . >a; ripwire . >b; diff -q a b`), so
a regenerated `GRAPH_REPORT.md` produces a clean diff — only real topology changes
show up in review. Only the `--index-out` cache artifact stamps a write time and is
documented as restore-equivalent rather than byte-identical; we do not commit it.
